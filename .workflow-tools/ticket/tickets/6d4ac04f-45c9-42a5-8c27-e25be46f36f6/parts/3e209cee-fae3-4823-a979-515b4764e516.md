Acceptance criteria amendment (agreed with requester 2026-09-02): the original phrasing 'both run to completion and produce Criterion output covering every scenario' is replaced. Full un-timeboxed statistical Criterion runs are not required.

New acceptance criteria (applies to both spec-api and session-api matrices):
- Each scenario is run individually as a real Criterion measurement (NOT --test dry-run mode), filtered to its exact scenario id.
- Each individual scenario invocation is wrapped in its own external timeout of 60s (flat first-pass cap).
- Each scenario is classified PASS (real Criterion mean/stddev captured within budget) or EXCEEDED (killed at cap; record elapsed wall time and any progress printed before the kill).
- Every scenario in each crate's matrix must have a recorded PASS or EXCEEDED classification -- EXCEEDED is acceptable, complete evidence, not a failure requiring rerun.
- The prior --test smoke-mode results (17/75 spec-api, 11/12 session-api) are NOT valid evidence toward this criterion: --test mode collects zero timing data. All scenarios must be (re-)run for real under the above regime.
- Criterion overhead (warm-up/measurement/sample-size) may be tuned down so fast scenarios don't waste their budget on fixed overhead, as long as real per-scenario timing is still produced.
