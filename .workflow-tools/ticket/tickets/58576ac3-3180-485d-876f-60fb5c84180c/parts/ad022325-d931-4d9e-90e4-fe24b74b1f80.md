## Implementation plan: spec extraction

### Established baseline
`memory-api/crates/memory-api` is deleted. `spec` must depend below its domain boundary on `memory_kernel` from `https://github.com/mankinskin/memory-kernel` (branch `main`), as completed by ticket `1b7e0c3d`. Commit the git dependency, never a relative `path`; use a root-only `[patch]` override for local development. The final patch-free build must resolve the remote kernel.

Create public crate `spec` that re-exports internal `spec-api`, has no default features, and owns feature-gated `spec`, `spec-mcp`, and `spec-http` bins using `transport-harness` from `memory-kernel`. This is the `ticket`-pilot consolidation shape from ticket `26da8f59`.

Keep `spec` types out of the neutral kernel. Any typed `EntityManifest` accessors move into `spec-api` extension traits using the identical `extra` keys so existing spec-store bytes remain compatible.

### Verified source surface
- API: `memory-api/crates/spec-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/spec-cli`, `memory-api/tools/mcp/spec-mcp`, `memory-api/tools/http/spec-http`.
- Viewer: `memory-viewers/spec-viewer`, including `frontend/dioxus`.

### Consumers to repoint
`memory-viewers/spec-viewer`, `memory-api/tools/mcp/rule-mcp`, `memory-api/crates/session-worktree-provision`, `memory-api/crates/memory-matrix`, `memory-api/crates/session-api`, `memory-api/crates/audit-api`, `memory-api/crates/ticket`, `memory-api/tools/cli/test-cli`, and `memory-api/tools/cli/rule-cli` currently consume `spec-api` (plus the legacy spec transports themselves).

### Execution
1. Fold the three legacy transport crates into feature-gated bins in public crate `spec`, retaining `spec`, `spec-mcp`, and `spec-http` names and their behavior/tests.
2. Move `spec-api`, the consolidated crate, and `spec-viewer` into the standalone `spec` repository; retain the viewer-to-HTTP contract.
3. Repoint every listed consumer to the published `spec` git dependency, then remove monorepo members and legacy paths.
4. Extract only after `feedback` and `test` are published because `spec-api` consumes both.

### Acceptance criteria
```bash
cargo test -p spec-api -p spec-cli -p spec-mcp -p spec-http
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
cd memory-viewers/spec-viewer/frontend/dioxus && npm run test:e2e:release
```
Validate the viewer in an external fullscreen Chromium-family browser and capture Playwright screenshots. `AGENTS.md` requires both browser verification and Playwright E2E for the viewer migration.

### Risk
Standalone proof remains blocked until `memory-kernel`, `feedback`, and `test` are published and resolvable by git URL; no committed relative dependency is acceptable.
