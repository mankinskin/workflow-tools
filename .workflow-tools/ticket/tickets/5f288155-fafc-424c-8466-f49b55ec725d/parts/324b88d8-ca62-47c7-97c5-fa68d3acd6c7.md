## Acceptance criteria

AC1. `workflow-tools/install/README.md`, `workflow-tools/README.md`, `workflow-tools/COMMANDS.md`, and the owning guidance instructions expose the same final command names and do not describe hypothetical behavior as shipped.

AC2. Documentation covers direct corpus profiles, source-published/local recipes, recipe permissions/staging, typed dependency classes, unsupported/unsafe/non-guidance classes, and external/fragment handling.

AC3. Documentation gives correct examples for plan-before-install, repository/user/system/explicit destinations, containment rejection, target-submodule preference, canonical fallback, and relative-link rewriting.

AC4. Documentation states the exact mutation boundary: plan/detection read-only; install requires a clean validated plan; autofix plan read-only; autofix apply explicit and reviewable; hook blocking with `--no-verify` escape hatch.

AC5. Documentation specifies stable output/exit behavior for clean success, blocking findings, missing artifacts, unsafe paths, stale autofix, unsupported recipes, failed post-audit, and rollback.

AC6. Fixture and Docker commands are documented with expected evidence, and the Meta-Workspace network smoke test is explicitly labelled non-deterministic/supplementary.

AC7. `artifacts.toml` and generated `COMMANDS.md` remain synchronized; user-created profiles are not incorrectly represented as runtime binary artifacts.

AC8. All new documentation links pass the guidance link audit and do not introduce ticket/spec/code references into publishable guidance files.

AC9. A reviewer can follow the documented flow from a repository finding to plan, install, final audit, or explicit autofix without consulting undocumented implementation details.
