# Derived-edge decisions

- Compute `transitive_depends_on`, reduction diagnostics, waves, and execution-order edges on demand in the ticket-domain graph query layer; never persist derived edges.
- Keep a stored `depends_on` edge authoritative. When a longer stored path implies the same pair, omit a duplicate latent edge and emit `redundant_depends_on` with the intermediary path.
- For an acyclic dependency DAG, use longest-path waves: a prerequisite-free ticket is wave 0 and every other ticket is `1 + max(prerequisite waves)`. Derive an execution-order edge from an earlier wave to a later wave, inverse to `depends_on`.
- Extend the existing graph-query result with opt-in derived edges, `waves`, and `diagnostics`; renderers consume that result without recomputing the graph. A directed cycle produces a cycle diagnostic and suppresses waves and execution-order edges for the affected component.
