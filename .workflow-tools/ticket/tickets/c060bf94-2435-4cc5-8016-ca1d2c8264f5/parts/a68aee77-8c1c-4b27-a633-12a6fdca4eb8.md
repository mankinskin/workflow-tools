What landed:
- `BoardEntry` gained `session_id`, `worktree_path`, and `branch`, all `Option<String>`.
- `BoardSnapshot` gained `active_worktrees: Vec<ActiveWorktree>`; `ActiveWorktree` carries `worktree_path`, `branch`, `session_ids`, `agent_ids`, `ticket_ids`, `entry_ids`, and a `conflicted` flag set when more than one session claims the same worktree.
- A `WorktreeConflict` error, mirroring the existing file-ownership conflict, rejects a check-in naming a worktree already held by a different session. The same session may share a worktree.
- Board rows are bincode blobs with no field names, so `deserialize_entry` now chains `BoardEntry` -> `BoardEntryV2` -> `BoardEntryV1`, richest shape first, because a shorter struct can parse a longer payload's prefix. Pre-change rows load with the three new fields absent, and absence stays distinguishable from an empty string.
- The three fields are accepted by the `board_check_in` MCP tool and the `ticket board check-in` CLI, and are emitted by `board_show` in human and JSON output.
- A new `board_worktrees` MCP tool and a new `ticket board worktrees` CLI subcommand expose the aggregate.

Two protocol defects were found by dogfooding the worktree workflow and have been corrected in `.agents/instructions/commit/branch-worktree.instructions.md`:
1. `git worktree remove` fails outright on a worktree containing initialized submodules, and needs a `submodule deinit` first plus `--force`.
2. `git submodule deinit` inside a worktree rewrites the `submodule.*` entries in the shared `.git/config`, silently deinitializing the main checkout's submodules; `git submodule init` in the main checkout repairs it.
