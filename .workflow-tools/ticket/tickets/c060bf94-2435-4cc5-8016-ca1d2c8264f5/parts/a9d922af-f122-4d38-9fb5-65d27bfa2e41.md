
## Extension (2026-08-06): session activity listing projection

Criterion 4 above lists active worktrees keyed by `worktree_path`. The session-anchored resolution work in `fa2ba34b` needs the complementary projection: a listing keyed by SESSION, answering "which sessions exist, what is each one working on, and which are still live" — so an agent or human can pick up or clean up work without reading the raw store.

## Additional Acceptance Criteria

- AC-L1: A session listing surface reports, per session: session id, assigned worktree path, branch, the ticket track being worked (the ticket ids associated with the session), an active/inactive flag, and a last-activity timestamp.
- AC-L2: The active flag is DERIVED, not stored as a duplicate source of truth — it is computed from the session's worktree assignment `status` (`Active` vs `Superseded`/`Invalidated`) together with activity recency, so it cannot drift from the assignment record.
- AC-L3: The listing accepts filter parameters, at minimum: active-only (default) and include-completed. A completed or superseded session is excluded by default and appears only when explicitly requested.
- AC-L4: The listing accepts a detail parameter controlling projection width — a compact form for scanning (id, worktree, active, last activity) and a full form adding the ticket track and branch. The compact form is the default so a routine listing stays token-cheap.
- AC-L5: Sessions with no worktree assignment appear with those fields explicitly absent rather than omitted from the listing or defaulted to a misleading value, consistent with criterion 6 above.
- AC-L6: The listing is exposed on both the CLI and the MCP surface, consistent with criterion 4.
- AC-L7: Tests cover: the derived active flag for each assignment status, default exclusion of completed sessions, both detail levels, and a session lacking a worktree assignment.

Out of scope (unchanged): creating or removing git worktrees, and verifying a recorded `worktree_path` exists on disk.
