## Implementation plan: test extraction

### Established baseline
The former `memory-api/crates/memory-api` base crate is deleted. Commit `memory_kernel` as the `https://github.com/mankinskin/memory-kernel` git dependency on branch `main`; keep relative paths in a root `[patch]` only (ticket `1b7e0c3d` proved remote resolution without a patch).

Create public crate `test` re-exporting `test-api`, with no default features and feature-gated bare `test` and `test-mcp` bins using `transport-harness` from `memory-kernel`, following the ticket-pilot consolidation (`26da8f59`). Keep test-specific typed `EntityManifest` accessors in `test-api` extension traits with byte-compatible `extra` keys, never in the kernel.

### Verified source surface
- API: `memory-api/crates/test-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/test-cli`, `memory-api/tools/mcp/test-mcp`.
- No `test-http` or viewer exists.

### Consumers to repoint
`context-stack/context-api`, `context-stack/context-insert`, `context-stack/context-read`, `context-stack/context-search`, `context-stack/context-trace`, `memory-api/crates/log-api`, `memory-api/crates/memory-matrix`, `memory-api/crates/session-api`, and `memory-api/crates/spec-api` consume `test-api` outside test's own transports.

### Blocking dependency (explicit)
`memory-api/tools/cli/test-cli` currently has a cross-repo cycle dependency on `log-api` (`test-cli` consumes `log-api`, while `log-api` consumes `test-api`) — the exact cross-repo cycle blocking log extraction identified in `a6d38372` ("Resolve test-cli/log-api/test-api dependency cycle blocking log extraction"). This ticket depends directly on `a6d38372` (narrower than the broader `866049e7` "break the test/log dependency cycle" edge, which is also retained): the cycle must be resolved — `test-cli`'s `log-api` import removed or restructured — before `test-cli` can be folded into the standalone `test` domain crate and published without re-introducing the cycle in the extracted repo.

### Execution
1. Confirm `a6d38372` has removed the `test-cli` → `log-api` cycle.
2. Separate the legacy `test-cli` → `log-api` dependency from the public `test-api` → `log-api` boundary: `log-api` consumes `test-api`, while `test-cli` consumes `log-api`. Preserve a one-way published dependency graph rather than creating a `test <-> log` git cycle.
3. Consolidate `test-cli` and `test-mcp` into public crate `test`, retaining `test` and `test-mcp` names and existing tests.
4. Move `test-api` and public crate `test` to the standalone repository and repoint every listed consumer.
5. Publish test before `spec`, `session`, and `log`, all of which consume `test-api`.

### Acceptance criteria
```bash
cargo test -p test-api -p test-cli -p test-mcp
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
```

### Risk
Extraction cannot land while the test/log cycle (`a6d38372`) is open — it is a hard prerequisite, not a soft ordering preference. Published `memory-kernel` and `log` availability are also required for final proof.
