## Functional requirements

1. The CLI exposes a `guidance` command family with at least `plan` and `install`; command parsing must reject missing source, selection, destination, or profile inputs with actionable errors.
2. A profile may be loaded from a source repository or local project/user configuration and must represent either a direct corpus/value or a recipe whose steps produce a corpus through download, generation, or compilation. Profile loading is data-driven and does not require a global profile database.
3. The profile contract must identify selected roots, source repository identity, recipe inputs, produced artifacts, and destination policy. Source paths are repository-relative and cannot escape the source root.
4. Dependency discovery builds a deterministic typed graph. At minimum, edges distinguish guidance-file references, profile/manifest references, generated/downloaded corpus inputs, submodule ownership, unsupported dependency kinds, and unsafe/non-guidance targets.
5. Graph resolution computes a stable transitive closure, detects missing nodes, duplicate destinations, cycles, ambiguous ownership, unsupported kinds, and unsafe paths before any write.
6. Destination resolution supports repository-local, user-wide, system-wide, and explicit path scopes. Canonical roots and explicit paths must be normalized, validated for traversal/symlink escape, and rendered in the plan.
7. Existing target submodules take precedence when source ownership maps to a matching target submodule. If the target submodule is absent, the artifact is placed at its canonical Guidance location and all affected relative references are rewritten from the final target path.
8. `plan` is read-only and emits stable machine-readable and human-readable output containing selected roots, dependency closure, destination mapping, rewrites, skipped external references, and blocking diagnostics.
9. `install` must execute only a validated plan, preserve file bytes unless a declared rewrite is required, refuse partial installation on blocking diagnostics, and report every created/updated path.
10. Re-running the same install with the same source revision, profile, selection, and destination is idempotent and produces no uncontrolled churn.

## Safety requirements

- No network, shell recipe, generator, compiler, or downloader runs without an explicit profile permission and an isolated, declared output path.
- No destination write follows a failed validation, unresolved dependency, unsafe path, or non-guidance portability error.
- Symlink and path normalization checks must be performed against the resolved filesystem, not only lexical strings.
