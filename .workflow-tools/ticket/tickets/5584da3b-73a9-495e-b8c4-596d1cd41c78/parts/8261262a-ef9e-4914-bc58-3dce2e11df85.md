## Implementation route

1. Add a dedicated guidance domain module under `workflow-tools/install/install-ctl/src/` rather than embedding graph logic in `main.rs` or the viewer command module.
2. Define typed input models for profile source, corpus item, recipe step, dependency edge, destination scope, planned artifact, rewrite, diagnostic, and plan result. Use serde-compatible representations so plans can be snapshot-tested.
3. Implement source/profile loading and canonicalization first; separate pure graph planning from filesystem effects and from recipe execution.
4. Implement a resolver that parses supported Markdown and profile references into typed edges, records unsupported/non-guidance edges instead of silently dropping them, and computes a deterministic topological order or a cycle diagnostic.
5. Implement destination mapping as a pure function over source ownership, target repository topology, selected scope, and explicit path. Add matching-submodule detection and canonical fallback mapping before link rewriting.
6. Implement rewrite generation from source-relative edge to final-target-relative edge, retaining URL and fragment-only links unchanged. Refuse to write when a rewrite would escape the destination root or become ambiguous.
7. Add plan serialization and CLI rendering. `plan` must be testable without network or writes; `install` consumes the same plan object and performs an atomic staged write/rollback strategy.
8. Integrate the new command without changing existing top-level artifact and viewer command behavior. Add only the minimum registry/catalog metadata needed for discoverability.
