## Required plan examples

- Direct corpus: select one prompt file; plan includes the requested file, its in-corpus Markdown closure, stable target paths, and no recipe execution.
- Source recipe: load a repository-published profile whose recipe produces a corpus in a declared staging directory; plan records recipe inputs, produced artifacts, and the resulting dependency closure.
- Local project profile: load a profile from the current repository; ensure no user/system state is read unless explicitly selected.
- User/system destination: resolve platform-specific roots through injectable path providers; test both valid targets and paths outside the selected scope.
- Relative relocation: source `a/prompt.md` references `../instructions/base.md`, while target placement changes both directories; plan rewrites the link to the correct target-relative path.
- Existing submodule: source ownership matches an initialized target submodule; plan places the artifact inside that submodule and retains an intra-submodule reference.
- Missing submodule: source ownership has no target checkout; plan places the artifact at the canonical guidance path and rewrites all incoming/outgoing relative links.
- Failure cases: missing dependency, cycle, duplicate destination, traversal attempt, symlink escape, unsupported recipe step, non-guidance target, and unresolved submodule mapping each produce a stable diagnostic and no write plan.
- Idempotence: two plans over identical inputs have byte-stable serialized output; a second install reports no uncontrolled changes.
