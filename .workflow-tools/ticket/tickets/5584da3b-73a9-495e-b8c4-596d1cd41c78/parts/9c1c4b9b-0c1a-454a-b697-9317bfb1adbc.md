## Validation contract

### Unit and integration commands

1. `cargo test -p install-ctl guidance` must pass all guidance parser, graph, destination, rewrite, submodule, plan, and install tests.
2. `cargo run -p install-ctl -- guidance plan --help` and `cargo run -p install-ctl -- guidance install --help` must exit 0 and list required inputs, destination scopes, dry-run/plan behavior, and failure semantics.
3. Run the guidance fixture integration test with a temporary destination and assert the serialized plan contains the expected artifact ids, edge types, closure order, final paths, and rewrites.
4. Run rejection fixtures and assert non-zero exit, stable diagnostic code, offending source/target, and zero destination mutations.
5. Run the idempotence fixture twice and compare destination tree hashes and normalized result summaries.

### Required evidence

- Record one validation spec per command family and link executions to ticket `5584da3b-73a9-495e-b8c4-596d1cd41c78`.
- Preserve plan snapshots and expected-result manifests under the fixture scope; do not use host user/system directories in tests.
- Report network-dependent recipe tests separately from deterministic local tests.

### Exit criteria

All AC1-AC10 have command-backed evidence, no blocking diagnostic remains in success fixtures, every rejection fixture proves no write, and `git diff --check` is clean for the touched implementation/test/docs paths.
