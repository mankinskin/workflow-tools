## Acceptance criteria

AC1. `install-ctl guidance plan --help`, `install-ctl guidance install --help`, and the selected profile/recipe input syntax are present and documented by Clap without changing existing command help or dispatch.

AC2. A valid direct-corpus profile and a valid recipe profile parse into the same normalized profile model; malformed TOML/JSON, missing required fields, unsupported recipe steps, duplicate artifact ids, and source-root escapes return non-zero errors naming the offending field/path.

AC3. For every supported dependency edge, the planner emits a stable edge type, source identity, target identity, ownership repository, and resolution status. The transitive closure is deterministic, cycle-aware, and contains each artifact once.

AC4. The planner rejects missing dependencies, cycles, duplicate final destinations, ambiguous profile ownership, path traversal, absolute source paths, symlink escapes, unsupported/unsafe recipe steps, and blocked non-guidance targets before any destination write.

AC5. Repository, user, system, and explicit destinations resolve through one tested destination abstraction. Explicit destinations are accepted only when they remain within the selected scope after canonicalization; platform path separators are normalized in output.

AC6. Existing target submodules are selected by verified repository ownership/path identity. When no matching submodule exists, the canonical guidance fallback is selected and every changed relative Markdown reference is emitted as an explicit rewrite.

AC7. `plan` performs no writes, recipe execution, network access, or mutation of ticket/spec/test stores. The test suite proves this with a read-only filesystem or unchanged tree assertion.

AC8. `install` refuses a plan with any blocking diagnostic, stages all writes under the destination, preserves unrelated files, and either completes atomically or leaves the destination at its pre-install state.

AC9. Installing the same normalized plan twice is idempotent; the second run produces no content drift and reports a stable no-op/update summary.

AC10. Focused tests cover valid direct corpus, valid recipe, all destination scopes, relocation rewrites, present/absent submodules, missing/duplicate/cyclic dependencies, traversal/symlink escapes, unsupported steps, and no-write-on-error behavior.
