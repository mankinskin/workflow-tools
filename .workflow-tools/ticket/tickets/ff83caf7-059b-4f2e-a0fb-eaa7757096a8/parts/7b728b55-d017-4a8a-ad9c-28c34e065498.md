## Worktree lifecycle commands

Extend `worktree-ctl` with explicit maintenance commands for inactive worktrees. `clean`, `commit`, `rebase`, `merge`, and `sync` accept repeatable `--worktree <selector>` arguments or `--all` for all managed worktrees. Existing single-selector forms remain compatible.

- `clean` removes only clean worktrees that are not ahead of local `main`, including worktrees fully behind `main`.
- `commit` stages the selected paths using `git add` semantics and commits only the requested selected worktrees; the trailing `-- <pathspec>...` filters staged paths.
- `rebase` and `merge` apply to every selected worktree in deterministic order.
- `sync` sorts selected worktrees by filesystem modification time, oldest first; for each worktree it completes rebase then merge before starting the next, and stops at the first failure so only one conflict is active.

All batch operations retain dry-run behavior and surface selector, safety, Git, and conflict failures.
