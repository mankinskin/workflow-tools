# Implementation Plan

## Established constraints and compatibility contract

- The former repository cycle is cleared by ticket `1b7e0c3d`: the deleted legacy `memory-api` base crate has been replaced by `memory_kernel` below `ticket-api` and its consumers. Do not restore that dependency.
- Resolve published dependencies by git URL, for example `memory-kernel = { git = "https://github.com/mankinskin/memory-kernel", branch = "main" }`. Committed manifests must not use relative paths. A superproject-root `[patch."https://github.com/mankinskin/memory-kernel"]` override may map `memory-kernel` to `memory-kernel` and `transport-harness` to `memory-kernel/crates/transport-harness` for local development only.
- Keep the public `ticket` crate as the domain entry point: re-export internal `ticket-api`, keep default features empty, and retain feature-gated `ticket`, `ticket-mcp`, and `ticket-http` binaries over `transport-harness`. The CLI binary is `ticket`, never `ticket-cli`.
- Keep ticket domain types out of the neutral kernel. `SpecRef`, `TicketPart`, `TicketRefEntry`, and typed `EntityManifest` extension traits remain in `ticket-api`, use the existing `extra` keys `related_specs`, `spec_ids`, and `parts`, and preserve byte-compatible on-disk manifests.

## Acceptance criteria and runnable checks

```bash
git submodule status ticket
git -C ticket remote -v
cargo build --manifest-path ticket/Cargo.toml --all-features
cargo test --manifest-path ticket/Cargo.toml --all-features
cargo run --manifest-path ticket/Cargo.toml --features cli --bin ticket -- --help
cargo run --manifest-path ticket/Cargo.toml --features mcp --bin ticket-mcp -- --help
cargo run --manifest-path ticket/Cargo.toml --features http --bin ticket-http -- --help
cargo test -p session-api -p audit-api -p session-capture-hook -p session-worktree-provision -p memory-matrix -p spec-cli -p rule-cli
cd memory-viewers/ticket-viewer/frontend/dioxus && npm run test:e2e:release
```

Acceptance requires the submodule to resolve on `main`; no committed relative path may remain in `ticket-api` consumer manifests; the public crate and all three binary contracts must pass; ticket manifest bytes remain compatible through the extension traits; and the viewer must pass the release E2E suite and external fullscreen Chromium-family browser verification with screenshots.
