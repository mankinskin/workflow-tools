## Implementation route

1. Add a small `git.rs` module under `workflow-tools/install/install-ctl/src/guidance/` mirroring `workflow-tools/session/crates/worktree-ctl/src/git.rs`'s style: a `run_git`/`git_command`-shaped helper wrapping `std::process::Command::new("git")`, with the same Windows extended-length-path (`\\?\`) normalization. This is a same-style reimplementation, not a cross-crate dependency on `worktree-ctl` (a separate binary/crate).
2. Add a `clone_shallow(url: &str, dest: &Path) -> Result<(), String>` function performing `git clone --depth 1 <url> <dest>`, returning the git stderr on failure.
3. Add `GuidanceCmd::Get(GuidanceGetArgs)` to the existing `GuidanceCmd` enum in `mod.rs`, with fields: `repository_url: String`, `select: Vec<String>`, `profile: Option<PathBuf>`, `target: PathBuf` (default `.`), `destination_scope`, `destination_path`, `keep_checkout: bool`, `json: bool` — reusing `DestinationScopeKind` and the existing rewrite-pair-style clap patterns already in this file.
4. Implement profile resolution: if `--profile` is given, resolve it relative to the cloned checkout root and call `load_profile` unchanged. If omitted, synthesize a `Profile` in memory (bypassing `load_profile`'s TOML parsing but reusing its validation helpers, in particular `validate_repo_relative`) with one direct `CorpusItem` per `--select` value.
5. Implement the command body: create a managed temp directory (via `tempfile::TempDir` or an explicit path under the system temp dir when `--keep-checkout` is set, since `TempDir` deletes on drop), clone into it, resolve the profile, build the plan via the existing `PlanInputs`/`build_plan` with `source_root` = the checkout, `target_root` = `--target`, then print the plan and either stop (blocking) or call the existing `install_plan` — reusing `run`'s existing `Plan`/`Install` bodies as the pattern to follow, not duplicating their printing/error logic.
6. Ensure cleanup runs on every exit path (success, blocking plan, install error) unless `--keep-checkout`; when kept, print the checkout path so the caller can inspect or reuse it.
7. Wire `Get` into `run(command: GuidanceCmd)` in `mod.rs` and into the top-level `main.rs` dispatch exactly like `Plan`/`Install`/`Autofix` are wired today.
8. Add focused tests using a *local* directory as the "clone source" by invoking the real `clone_shallow` against a `file://`-style local path, or, where a real git binary in the test environment is undesirable, a seam that allows substituting `clone_shallow` in tests (an injectable clone function) so unit tests for profile synthesis, cleanup, and plan/install wiring do not require real network access. Mirror `workflow-tools/install/install-ctl/src/guidance/tests.rs`'s existing patterns (temp roots, no real host directories).

## Ownership boundaries

- This ticket owns: the new `get` subcommand, the local `git.rs` clone helper, profile synthesis from bare `--select` paths, and checkout lifecycle (create/keep/delete).
- This ticket does not modify `plan`, `install`, `autofix`, `profile::load_profile`'s TOML-parsing contract, the dependency graph/closure engine, or the audit/portability classification work (tickets `5584da3b`, `76abb9a1`, `07601b9b`, `5f288155`, all already done) — it only calls their existing public entry points.
- Documentation for `get` is included in this ticket's acceptance criteria (a small addition to the existing `install/README.md` command family section, not a separate ticket), since it is one additive command rather than a new subsystem.
