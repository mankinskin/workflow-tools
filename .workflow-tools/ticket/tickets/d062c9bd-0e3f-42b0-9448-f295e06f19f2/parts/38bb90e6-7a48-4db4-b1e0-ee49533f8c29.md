## Required examples

- Minimal one-command install: `install-ctl guidance get https://example.com/some-repo.git --select workflow-tools/.agents/agents/explore.agent.md` — no `--profile`, no `--target` (defaults to `.`); clones, synthesizes an implicit direct-corpus profile from the bare path, plans, installs into `.`, deletes the checkout.
- Explicit profile inside the source repo: `--profile install/guidance-profiles/agents.toml --select explore` — profile path is resolved against the freshly cloned checkout root, not the caller's local filesystem.
- `--keep-checkout`: after a successful install, the managed clone directory still exists at the printed path; a second manual `guidance plan`/`install` against that path behaves identically to today's expert-facing flow.
- Blocking plan: a selected artifact has a missing dependency or a non-guidance reference; `get` prints the same diagnostics `plan` would, exits non-zero, performs no writes, and still deletes the checkout (no `--keep-checkout`).
- Clone failure: an invalid or unreachable URL produces a clear error naming the clone step and the underlying git error text; no plan or install is attempted; no managed directory is left behind.
- Idempotence: running the same `get` command twice against the same source/select/target reports the second run's install as unchanged, consistent with `install`'s existing idempotence guarantee.
- Bare-path validation: a `--select` value that is absolute or escapes the repository root is rejected by the same `validate_repo_relative` check `load_profile` already applies to profile-declared paths — no bypass for the profile-less path.
