## Acceptance criteria

AC1. `install-ctl guidance get --help` documents the repository-url positional, required `--select`, and optional `--profile`/`--target`/`--destination-scope`/`--destination-path`/`--keep-checkout`/`--json`, with `--target` defaulting to `.`.

AC2. `plan`, `install`, and `autofix` behavior, flags, and output are unchanged; existing focused tests for those subcommands continue to pass unmodified.

AC3. With `--profile` omitted, each `--select` value is treated as a bare repo-relative source path and installed as a direct corpus item; with `--profile` given, `--select` resolves against that profile's declared corpus ids exactly as `plan`/`install` do today.

AC4. The clone step shells out to the system `git` binary (`git clone --depth 1`) via a local helper module styled after `worktree-ctl/src/git.rs`; no `git2`/`gix` dependency is added to `Cargo.toml`.

AC5. A clone failure (missing git binary, bad URL, network error) produces a non-zero exit with an actionable error naming the clone step, performs no plan/install, and leaves no managed directory behind.

AC6. A blocking plan (from either an explicit profile or a synthesized one) is printed with the same diagnostics `plan` emits, exits non-zero, performs zero writes to `--target`, and still deletes the managed checkout unless `--keep-checkout` was given.

AC7. A clean plan is installed via the existing `install_plan` unchanged; the managed checkout is deleted after completion unless `--keep-checkout`, in which case its path is printed and the directory is left intact.

AC8. Synthesized profile paths are validated with the same `validate_repo_relative` rejection rules (absolute path, traversal) as profile-declared paths; a rejected path produces the same class of diagnostic, not a silent skip.

AC9. Running the same `get` invocation twice against the same source/select/target is idempotent: the second install reports no uncontrolled changes, consistent with `install`'s existing guarantee.

AC10. Focused tests cover: profile-less bare-path install, explicit in-repo profile, `--keep-checkout` retention, blocking plan with no writes and cleanup, clone failure with no plan/install attempted and no leftover directory, and idempotent rerun — using an injectable clone step so tests do not require real network access.
