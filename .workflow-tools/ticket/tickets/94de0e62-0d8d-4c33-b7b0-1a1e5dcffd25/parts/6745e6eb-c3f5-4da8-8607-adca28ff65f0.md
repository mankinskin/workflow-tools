## Implementation plan: session extraction

### Established baseline
`memory-api/crates/memory-api` is deleted. Use `memory_kernel` from `https://github.com/mankinskin/memory-kernel` branch `main` as a committed git dependency; local paths are root `[patch]` overrides only (ticket `1b7e0c3d` established the patch-free build).

Create public crate `session` re-exporting `session-api`, with an empty default feature set and feature-gated `session` and `session-mcp` bins built on `transport-harness` from `memory-kernel`, mirroring the ticket-pilot consolidation (`26da8f59`). Implement session-domain typed manifest accessors in `session-api` extension traits with byte-compatible `extra` keys; do not leak session types into the kernel.

### Verified source surface
- API: `memory-api/crates/session-api`.
- Legacy transports to consolidate first: `memory-api/tools/cli/session-cli`, `memory-api/tools/mcp/session-mcp`.
- Also in scope: `memory-api/crates/session-capture-hook` and `memory-api/crates/session-worktree-provision`, both of which consume `ticket-api` directly and must move alongside `session-api`.
- No `session-http` or viewer exists.

### Consumers to repoint
`memory-api/crates/session-workspace-resolver`, `memory-api/crates/audit-api`, `memory-api/crates/memory-matrix`, `memory-api/crates/session-capture-hook`, `memory-api/tools/mcp/mcp-toolmon`, and `memory-api/tools/cli/audit-cli` consume `session-api` outside session's own transports.

### Execution
1. Consolidate `session-cli` and `session-mcp` into public crate `session`, preserving binary names and current tests.
2. Move `session-api`, `session-capture-hook`, and `session-worktree-provision` into the standalone session repository.
3. Repoint every listed consumer to the published session git dependency; remove old monorepo paths only after consumers compile against it.
4. Session cannot cut over to a published `ticket` git dependency until `ba4aaa9c` (the `ticket` domain-crate extraction's consumer-repoint step) is complete — `session-api`, `session-capture-hook`, and `session-worktree-provision` all depend on `ticket-api`. This is the concrete blocker, narrower than a blanket "after feedback, test, rule, spec" ordering.
5. Extract after `feedback`, `rule`, and `spec` are published, since `session-api` consumes all three in addition to `ticket-api`.

### Acceptance criteria
```bash
cargo test -p session-api -p session-cli -p session-mcp
cargo build --manifest-path "$TOOL_REPO/Cargo.toml" --no-default-features
cargo test --manifest-path "$TOOL_REPO/Cargo.toml" --all-features
cargo test --workspace
```

### Risk
A standalone proof must wait for published `memory-kernel`, `ticket` (consumer-repoint complete via `ba4aaa9c`), and sibling APIs `feedback`, `rule`, and `spec`; committed relative paths are forbidden. Note: a `depends_on` edge from this ticket to `ba4aaa9c` was attempted and rejected by the ticket store as a false-positive dependency cycle (a diamond shape, not an actual cycle — parent tracker `858c5286` already depends on both directly). Recorded here in text as a known store limitation rather than a graph edge.
