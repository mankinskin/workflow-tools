## Acceptance review

**Verdict: accepted for completion with inherited baseline failures documented.** No Ticket-domain acceptance criterion is blocked by this review.

- **Core and capabilities:** `TicketStore` implements kernel `DomainStore` plus only the supported typed create, read, update, delete, and list capabilities. Ticket lifecycle and link semantics remain in TicketStore.
- **API compatibility:** the adapter retains `TicketId`, `TicketManifest`, `IndexedTicket`, `StorageError`, Ticket-specific create/update/list inputs, and existing domain extensions by forwarding to existing TicketStore methods.
- **Workspace and transport behavior:** CLI, MCP, and HTTP entry points use explicit selected-workspace resolution and canonical Ticket writes. Explicit `--index-root` precedence and managed-worktree Board routing are covered by regressions. Canonical Ticket roots map back to their owner workspace in the HTTP registry.
- **Read-only and legacy behavior:** read-only resolution does not initialize a store; `.ticket` remains readable in read-only mode; create/open resolves to `.workflow-tools/ticket`; legacy and duplicate-layout cases return structured diagnostics.
- **Isolated read-back:** a temporary fixture reads back created and updated entities from the selected canonical store and asserts that parent, sibling, and ambient stores were not initialized.
- **Lifecycle/link validation:** the existing Ticket lifecycle and link-validation methods remain the implementation; the focused `validate_links_tests` gate passes.
