## Responsibility

Expose equivalent CLI/MCP create, edit, save, publish, and readback operations by calling the API and returning its IDs, revisions, state, and diagnostics.

## Interfaces And Dependencies

Consumes `mission-typed-api-lifecycle`, `mission-typed-api-publication`, and `mission-typed-api-order`; provides canonical operation behavior to guidance.

## Behavior

Both transports accept typed authoring input and use API bootstrap/order/path/persistence/rendering. An incomplete draft can be saved and read back; publish applies required command/checkpoint readiness. MCP parity is proven through initialized stdio JSON-RPC (`initialize`, notification, `tools/list`, `tools/call`), not help output.

## Boundaries And Failure Cases

Adapters do not allocate UUIDs, copy prompts into Parts, manually assemble Markdown/manifests, execute validation commands, schedule work, or repair installers. Equivalent malformed/stale/publish-not-ready errors leave accepted data unchanged.

## Provider/Consumer Contract

Guidance consumes `mission-typed-adapter-parity` and `mission-typed-adapter-publication`.

## Examples

CLI saves an empty draft and MCP reads the returned ID/revision; both reject publish until a waypoint includes its command/checkpoint and both then return the same publication state.

## Evidence

Positions: adapters are `partial`; typed lifecycle mapping is `not-implemented`. W3 runs `cargo test -p mission --features cli,mcp --test direct_transports` once, including real CLI/MCP parity and generated-Markdown readback. Final full suites are W5-only.

## Scope

Transport adaptation only; API semantics, migration, and guidance authoring are excluded.
