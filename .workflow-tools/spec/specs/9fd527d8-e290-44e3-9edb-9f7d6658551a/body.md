## Naming Conventions

Use `mission-typed-api-*` criteria. `save` means integrity-checked draft persistence; `publish` means full readiness-checked generated-output publication. A `PartSource` is typed JSON referenced by structured Mission data; `part_markdown` is generated output, not source.

## Responsibility

The API allocates UUIDs, bootstraps records, creates/edits/saves/publishes, derives immediate predecessor links from authored total order, resolves safe Part paths, persists typed sources, and renders Markdown. It preserves accepted identity/history/revisions/results and foreign ownership.

## Interfaces And Dependencies

Facade and transports consume API operations; they neither allocate identity nor assemble manifests/Markdown. The API provides typed draft diagnostics to adapters and typed source/persistence criteria to migration.

## Behavior

W1 first moves existing responsibility without behavior change. Thereafter a save accepts an empty or incomplete draft if typed values and references are valid; it rejects malformed values, invalid references, absolute/traversal/escape paths, and preserves the accepted revision on failure. Publish requires a complete ordered set, every waypoint's validation command and checkpoint, and derives each non-first immediate predecessor. It emits Markdown projections only; source preserves distinct prompt and Part information.

## Boundaries And Failure Cases

No scheduler or command execution occurs. Save never relaxes structural integrity; publish never accepts optional gates. Unsafe paths, duplicate/missing sequence members, invalid typed content, or stale revisions are rejected atomically. No silent conversion or Part fallback is permitted.

## Provider/Consumer Contract

Adapters consume `mission-typed-api-lifecycle`, `mission-typed-api-publication`, and `mission-typed-api-order`. Migration consumes `mission-typed-api-source` and `mission-typed-api-safe-paths`.

## Examples

An API-created draft has an ID and revision while it has zero waypoints. After a waypoint with distinct prompt and `PartSource` is added, save succeeds; publish fails until its command and checkpoint exist, then renders Markdown with the API-derived predecessor.

## Evidence

Positions: API/facade are `partial`; typed source, draft-save distinction, and API UUID ownership are `not-implemented`. W1 runs `cargo test -p mission-api --test ownership_api` and `cargo check -p mission --features cli,mcp` once; W2 runs `cargo test -p mission-api --test typed_source` once. Final full suites are W5-only. Required focused evidence covers UUID/bootstrap, incomplete save, publish rejection, safe paths, distinct prompt/Part round trip, serial derivation, stale-write preservation, and Markdown-only output.

## Scope

Owns API/facade lifecycle and typed persistence contract only; transport wire adaptation, migration execution, and guidance are sibling scope.
